# Select a useful public delivery

Fictional example. Permissions stated here belong only to this scenario.

## Input and natural request

The author permits sharing a setup guide, a limitations note, synthetic tests and
the required license text.
A personal career-planning note is private. A useful method paragraph is mixed
with that note; permission to share the method paragraph has not been established.

> Review these materials for new users of a public repository. Show what to keep,
> adapt, exclude or clarify. Keep originals intact and do not publish anything.

## Illustrative content map

| Material | Recipient value | Permission | Urgency | Action |
|---|---|---|---|---|
| Setup guide and required license | Essential | Allowed | Before sharing | Keep |
| Limitations and useful synthetic tests | Useful for honest use | Allowed | Before sharing | Keep |
| Personal career planning | Outside this delivery's purpose | Private | Before sharing | Exclude from this payload |
| Useful method paragraph mixed with private text | Potentially useful | Unclear for this destination | Resolve before including it | Clarify; adapt a separate permitted copy only when authorized |

The same topic does not establish recipient value or permission. Exclusion means
omission from the selected payload, not deletion. Review can also concern an
already-public repository; local presence alone does not prove remote exposure.

## When to use another workflow

A code audit or secret scan alone does not answer this audience-and-disclosure
question. Approval of a content map is not blanket approval to upload later text.
